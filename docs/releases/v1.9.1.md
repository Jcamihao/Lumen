# Release Notes - v1.9.1 (Lumen)

Tag criada na `develop` em 2026-11-23 pela regra de tags por task. Patch: **backend não pendura quando o Redis cai** (merge `fix/redis-queda-backend`), o risco registrado na v1.9.0.

## O que mudou
- `CacheQueueService` reescrito com as assinaturas públicas iguais: cliente ioredis com `enableOfflineQueue: false`, `maxRetriesPerRequest: 1`, `commandTimeout` de 1500 ms e `lazyConnect` — o boot não espera a conexão.
- Disponibilidade por eventos (`ready` → up; `close`/`end`/`error` → down), com log uma vez por transição. Motivo do erro só por código ou nome, nunca a mensagem.
- Todo método público passa por `runCommand`: limite de tempo, captura e valor degradado — sem Redis o pedido segue degradado em vez de pendurar. `hitRateLimitWindow` virou um script Lua único (INCR/PTTL/PEXPIRE); falha devolve `null`.
- Fila com limite de 2000 ms e listener de erro; shutdown com limite de 1000 ms; URL inválida não impede o boot (modo degradado).
- 18 testes novos de unidade (15 rodadas de estabilidade, todas verdes) e integração real com Redis 7 descartável: pausa, stop, start e boot com Redis fora.

## Limite
- `RateLimitGuard` e a regra do WhatsApp não mudaram; a decisão de segurança em cache de rate limit ausente continua a mesma do item 5 (número não vinculado sem Redis é ignorado).
