## Escopo (so isto)
1. Cliente (telegram-bot.client.ts): suportar inline keyboard (linhas de {text, callback_data}), teclado fixo de resposta com 1 botao "Menu" (persistente: is_persistent true, resize_keyboard true; NAO one_time), editMessageText(chatId, messageId, text, inline?), answerCallbackQuery(callbackQueryId). getUpdates passa a pedir allowed_updates ['message','callback_query']. Manter o teclado temporario Confirmar/Cancelar de hoje. Para testar clientes externos, espione o metodo privado de request (padrao do projeto).
2. Entrada: o parser de updates reconhece callback_query (chat id e message id vem de callback_query.message; id do callback; data) e entrega ao adaptador como inbound do tipo callback. Descartar (e ainda assim avancar o offset como hoje) callback sem message, de chat nao privado ou com data invalida. Offset por update lido continua valendo.
3. Adaptador: callback so vale com data no formato "m:<nodeId>" (<= 64 bytes; prefixo mais id da arvore da 12.1a; id fora da arvore => tratado pelo motor como raiz; formato fora do padrao => ignora). Fluxo: rate limit (mesma janela do chat); chat sem vinculo => answerCallbackQuery vazio e ignora (sem resposta, falha fechada igual ao de hoje); chat vinculado => answerCallbackQuery (best effort, nunca bloqueia) e conversation.handleMenuAction({ userId do vinculo, channel TELEGRAM, messageId = id do callback, nodeId, receivedAt }). O dono vem SO do vinculo chat->usuario, nunca do callback. DUPLICATE => nao reenvia. Reply kind MENU vindo de clique => editMessageText no lugar com o inline keyboard do no; se a edicao falhar (mensagem velha, "not modified", apagada), cair para enviar mensagem nova (log sem texto do usuario). Outro kind (resultado, instrucao, ajuda) => mensagem nova com o teclado fixo "Menu".
4. Reply kind MENU vindo de TEXTO (usuario digitou "menu", "voltar", /menu, /start) => mensagem NOVA com inline keyboard. Cada no: um botao por opcao (uma por linha); em submenu, ultima linha com "Voltar" (backId) e "Menu" (topId) quando existirem. Texto do menu com escapeHtml; rotulos dos botoes sao texto puro (sem HTML). Respeitar limites do Telegram (callback_data 64 bytes; ate 8 botoes por linha, 100 por teclado).
5. Teclado fixo "Menu": anexado a toda resposta de texto enviada ao usuario vinculado que NAO seja Confirmar/Cancelar (assim ele volta depois da confirmacao) e a mensagem de vinculo feito. O texto "Menu" digitado cai na palavra de saida do motor.
6. Comandos: adicionar /menu ('menu') e /start ('menu', so para chat vinculado; chat sem vinculo segue o fluxo de vinculo de hoje: nao quebre) em COMMAND_PHRASES e BOT_COMMANDS (setMyCommands). Os atuais continuam.
7. Gate TELEGRAM_WRITES_ENABLED: confirme onde vive hoje e prove em teste que clique de menu que abre escrita com escrita desligada NAO grava (so orienta o app), igual a mensagem de texto. Sem escrita nova.
